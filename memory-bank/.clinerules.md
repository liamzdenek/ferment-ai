# Ferment AI Project Intelligence

This file captures important patterns, preferences, and project intelligence that help work more effectively with the Ferment AI project.

## Project Patterns

### Configuration Patterns

1. **Use AWS CDK Constructs Library**
   - Use the actual "constructs" npm package from AWS CDK
   - Follow the CDK pattern of `new ConstructType(scope, id, props)`
   - Maintain proper scope hierarchy

2. **L1/L2/L3 Construct Hierarchy**
   - L1: Core primitives (VirtualModel, AgentContext, Tool, etc.)
   - L2: Combinations of L1 constructs for common patterns
   - L3: High-level, domain-specific constructs

3. **Declarative Over Imperative**
   - Configuration should be declarative, describing what should exist
   - Runtime logic should be separate from configuration

### Journal Patterns

1. **Journal as Source of Truth**
   - All system state derives from the journal
   - Journal is append-only during execution
   - Events are categorized by type

2. **Event Publishing**
   - Components publish events to the journal
   - No direct state modification
   - Clear event structure with source, target, payload

3. **Event Subscription**
   - Components subscribe to relevant events
   - Derive state from events
   - React to state changes

### API Patterns

1. **Completely Stateless API**
   - No server-side state storage
   - Client maintains and passes journal state
   - Each request is self-contained

2. **Streaming Updates**
   - Real-time streaming of events
   - Journal updates included in stream
   - Final journal state returned at completion

3. **Clean Separation of Concerns**
   - API layer separate from execution logic
   - Clear interfaces between components
   - Minimal dependencies

### Tool Patterns

1. **Schema Validation**
   - Use Zod for input/output validation
   - Clear error messages for validation failures
   - Convert schemas to JSON Schema for documentation

2. **Error Handling**
   - Surface errors to the invoking agent
   - Capture errors in the journal
   - Provide context for debugging

3. **Tool Registration**
   - Tools are registered with agent contexts
   - Tools publish results to the journal
   - Tools have access to the full execution context

## Critical Implementation Paths

### Journal System

The journal system is the core of Ferment AI:

1. **Event Structure**
   ```typescript
   interface JournalEvent {
     id: string;
     type: string;
     timestamp: string;
     source?: string;
     target?: string;
     payload: any;
     metadata?: Record<string, any>;
   }
   ```

2. **Journal Operations**
   - `append(event: JournalEvent): void`
   - `query(filter: EventFilter): JournalEvent[]`
   - `subscribe(filter: EventFilter, callback: (event: JournalEvent) => void): Subscription`
   - `serialize(): string`
   - `deserialize(data: string): Journal`

3. **Event Flow**
   - Components publish events
   - Journal notifies subscribers
   - Subscribers update their state
   - State changes trigger actions
   - Actions publish new events

### Agent Context

Agent context reconstruction is critical:

1. **Context Building**
   - Filter relevant events from journal
   - Construct prompt from events
   - Include system message, history, and tools

2. **LLM Invocation**
   - Send prompt to LLM
   - Stream response tokens
   - Parse tool invocations
   - Handle errors

3. **Tool Handling**
   - Validate tool input
   - Execute tool
   - Capture result
   - Return result to agent

## Known Challenges

1. **Journal Size Management**
   - Large journals may exceed context windows
   - Need efficient serialization/deserialization
   - May need compression or selective filtering

2. **Concurrency Management**
   - Multiple agent contexts running concurrently
   - Need to manage resource contention
   - Ensure proper event ordering

3. **Error Propagation**
   - Errors need to be surfaced to agents
   - Agents need to handle errors appropriately
   - System needs to recover from errors

4. **Testing Complexity**
   - Complex agent interactions are hard to test
   - Need sophisticated mocking
   - Deterministic testing is challenging

## Evolution of Project Decisions

1. **Initial Design**

2. **Key Decisions**
   - Using AWS CDK constructs library
   - Focusing on single-user performance first
   - Prioritizing configuration language and journal design

3. **Future Considerations**
